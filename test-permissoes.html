Página auxiliar independente da interface principal. Ela autentica com Google, mas não executa a verificação claim_allowed_user do aplicativo; assim, é possível testar as políticas do banco com uma conta autenticada e não autorizada.

Cuidados: não use chaves secretas nem service_role. Os testes de escrita desta página só criam, alteram ou excluem registros na tabela items com um nome identificável de teste. Para testar atualização/exclusão de outro usuário, informe somente o ID de um item descartável criado especificamente para este teste.

Como interpretar

  • SELECT retornou linhas: a conta conseguiu ler os registros retornados; verifique se essa leitura é permitida pela regra de negócio.
  • SELECT retornou zero linhas: não prova, sozinho, que o acesso foi negado. A tabela pode estar vazia ou a RLS pode filtrar as linhas.
  • INSERT/UPDATE/DELETE bloqueado: resultado esperado para uma conta sem permissão, desde que a operação tenha sido testada com um alvo válido quando aplicável.
  • UPDATE/DELETE afetou zero linhas: não considere isso prova definitiva de bloqueio; a política pode filtrar o registro ou o ID pode não existir.
  • Um erro de rede, sessão expirada ou tabela inexistente não é um resultado conclusivo de RLS.
